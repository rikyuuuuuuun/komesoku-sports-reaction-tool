# ヒリヒリ・ハンデ帳

ゴルフ仲間うちのコンペ用ハンデ計算Webアプリです。
「前回ビリだったから今回は確実に1位」ではなく、**毎回だれが勝つか読めない接戦**になるようにハンデを出します。

## 使い方

1. 「メンバー」で仲間を登録します(名前と、だいたいの平均スコア)。
2. 「今日のハンデ」で今日回るメンバーを選ぶと、各自のハンデと優勝確率、ヒリヒリ度(1位と2位が2打差以内になる確率)が出ます。
3. 上がったらグロスを入れて「このラウンドを記録」。次回のハンデの目安も表示されます。
4. 「成績」で通算の優勝回数や、全員が均等だった場合の優勝回数と比べられます。

ネット = グロス − ハンデ。一番上手い人がハンデ0になります。

## ハンデの決め方

| | 内容 |
|---|---|
| 実力推定 | 直近16ラウンドのスコア(パー比)を、新しいほど重く(1ラウンド古くなるごとに×0.9)平均。最初は自己申告の平均スコアを「2ラウンド分」として混ぜる |
| ハンデ | 実力推定の差をそのままハンデに → 全員のネットの見込みが揃う |
| 大叩き・まぐれ | その時点の実力推定から±8打を超えた分はカット。わざと崩してもハンデはほとんど増えない |
| 優勝確率の微調整 | スコアのブレが大きい人は一発がある分有利なので、4000回のシミュレーションで全員の優勝確率が揃うよう0.5打単位で調整 |

1回のラウンドでハンデが動くのは1打前後なので、負けた人が次に必ず勝てる設計にはなっていません。

設定(「しくみ」タブ)で、最近の調子の反映の強さ、カット幅、上手い人ボーナス(ハンデを一律に減らす)、ハンデの刻みを変えられます。

## シミュレーション結果

実力差のある4人(平均84/90/97/104、ブレも人それぞれ)が24ラウンド回るシーズンを200回シミュレーション(`node simulate.js 200`)。

| 方式 | 各人の優勝率 | 前回ビリが次に優勝 | 前回優勝が次も優勝 | 2打差以内の決着 |
|---|---|---|---|---|
| ハンデなし | 88 / 11 / 1 / 0% | 1% | 79% | 22% |
| 前回の差を埋める | 19 / 23 / 27 / 31% | 49% | 12% | 34% |
| **このアプリ** | **22 / 24 / 26 / 28%** | **28%** | **26%** | **41%** |

理想はすべて25%。「前回の差を埋める」方式だとビリの人が約半分の確率で次に勝ってしまい、勝ち負けが交代制になります。

## ファイル

```text
golf-handicap/
├─ SPEC.md              # 仕様書(画面・データ・計算式・検証用の数値)
├─ CHATGPT_PROMPT.md    # ほかのAIに作り直してもらうときの頼み方
├─ index.html           # 画面
├─ app.js               # 画面の処理と保存
├─ handicap.js          # ハンデ計算エンジン(ブラウザ/Node 共通)
├─ simulate.js          # 方式比較のシミュレーション
├─ build.js             # 1ファイル版を作る → dist/hirihiri-handicap.html
├─ examples/worked-example.json  # 計算例(「読み込む」で取り込める)
└─ test/handicap.test.js
```

## 動かし方

```sh
cd golf-handicap
python3 -m http.server 8000   # http://localhost:8000 を開く
node --test test/handicap.test.js
node simulate.js 200
node build.js                  # 1ファイル版 dist/hirihiri-handicap.html を作る
```

ローカルで開いた場合、データはそのブラウザの localStorage に保存されます。
「しくみ」タブの「書き出す」「読み込む」で別の端末へ移せます。
claude.ai のアーティファクトとして開いた場合は、共有した仲間全員で同じデータを使えます。
