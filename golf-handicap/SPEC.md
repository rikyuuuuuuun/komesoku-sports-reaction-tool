# ヒリヒリ・ハンデ帳 仕様書

ゴルフ仲間うちのコンペで使うハンデ計算Webアプリの仕様です。
この文書だけで同じアプリを作り直せるように、目的・画面・データ・計算式・検証用の数値をすべて書いています。

---

## 1. 目的と設計方針

- 仲間うちのコンペで、**毎回だれが勝つか読めない接戦**にする。
- 「前回ビリだったから今回は確実に1位」という設計にはしない。負けた人は少し有利になるだけ。
- わざと大叩きしてハンデを稼ぐ作戦が効かないようにする。
- 実力が違う人どうしでも、全員の優勝確率がほぼ同じ(4人なら各25%前後)になることを目標にする。

達成の方法:

1. 各自の「実力推定」(最近のスコアの重み付き平均)の差をハンデにする → 全員のネットの見込みが揃う。
2. 1ラウンドの影響を小さくし、推定から大きく外れたスコアはカットする。
3. スコアのブレが大きい人(一発がある人)は有利になるので、シミュレーションで優勝確率が揃うよう微調整する。

---

## 2. 用語

| 用語 | 意味 |
|---|---|
| グロス | 実際の打数 |
| ハンデ | グロスから引く打数。一番上手い人が0 |
| ネット | グロス − ハンデ。少ない方が上位 |
| パー比 | グロス − そのコースのパー |
| 申告平均 | メンバー登録時に入れる「だいたいの平均スコア」(パー72換算) |
| 実力推定 E | 計算で出した、その人の見込みスコア(パー比) |
| ブレ σ | その人のラウンドごとのスコアのばらつき(標準偏差) |
| ヒリヒリ度 | 1位と2位のネットの差が2打以内になる確率 |

## 3. 画面

スマホで使う前提の1カラム。上部にアプリ名とタブ。タブは4つ。

### 3.1 今日のハンデ(最初に開く画面)

1. **今日回るメンバー**:登録メンバー(お休み中を除く)をチップで表示。タップで参加/不参加を切り替え。初期状態は全員参加。
2. **今日のハンデ**:参加者が2人以上のとき表示。
   - 上段に3つの数字:ヒリヒリ度(%)、1位と2位の差の予想平均(打)、優勝確率の差(一番高い人 − 一番低い人、pt)。
   - 表:名前 / ハンデ / 前回比 / 優勝確率(棒グラフ+%)。ハンデの小さい順。
   - 前回比 = 今回のハンデ − その人が前回のラウンドで使ったハンデ。初参加なら「初」。増えたら赤、減ったら緑。
   - 棒グラフには「全員同じ確率(1/人数)」の位置に線を引く。
3. **スコアを入れる**:日付(初期値は今日)、コース名、パー(初期値72)。参加者ごとにグロスを入力し、ネットをその場で表示。
   - 2人以上入力されたら「いまの順位」を表示(1位の名前、2位との差、全員の順位とネット)。
   - 「このラウンドを記録」で保存。グロスは50〜200のみ有効。有効な入力が2人未満なら保存しない。
4. **記録しました**(保存直後のみ表示):優勝者、2位との差、全員の順位・グロス・ネット・**次回ハンデの目安**(同じメンバーで回った場合)と今回からの増減。

### 3.2 成績

- **通算成績**:名前 / 回数 / 優勝回数 / 均等なら(全員の優勝確率が同じだった場合の期待優勝回数 = 各ラウンドの 1/参加人数 の合計) / 実力推定(72 + E) / 最近5ラウンドの順位(例「1/4」)。優勝回数の多い順。
- **ラウンド履歴**:新しい順。日付・コース・パー・1位と2位の差、順位表(順位 / 名前 / グロス / ハンデ / ネット)。削除ボタン(画面内で確認してから削除)。

### 3.3 メンバー

- 追加フォーム:名前(20文字まで、重複不可)、申告平均(60〜160、初期値100)。
- 一覧:名前 / 申告平均(その場で編集可) / ラウンド数 / 実力推定 / 状態。
- 記録のある人は削除不可。「お休み」に切り替えると今日のメンバー候補に出なくなる。記録のない人は削除可(画面内で確認)。

### 3.4 しくみ・設定

- 「なぜ毎回接戦になるのか」の説明(第1章の3点+大叩きカット)。
- シミュレーション結果の比較表(第7章)。
- 設定(全員共通):

| 設定 | 選択肢 | 標準 |
|---|---|---|
| 最近の調子の反映 | 強め 0.8 / 標準 0.9 / ゆっくり 0.95(= 減衰率 r) | 0.9 |
| 大叩き・まぐれのカット | ±6 / ±8 / ±10打(= C) | 8 |
| 上手い人ボーナス | なし / 10% / 20% / 30%(= ハンデを一律に縮める割合 b) | なし |
| ハンデの刻み | 0.5打 / 1打 | 0.5 |
| 優勝確率で微調整 | オン / オフ | オン |

- データの書き出し(JSONテキストをコピー)と読み込み(貼り付け → 画面内で確認 → 取り込み)。

### 3.5 メンバーがいないとき

サンプルの4人と8ラウンドを画面にだけ表示し、「サンプル表示中」と明示する。サンプルは保存しない。最初のメンバーを追加したら消す。サンプル中は記録できない。

## 4. データ

保存先はどこでもよい(localStorage、共有DB など)。書き出し形式は次のJSON。

```json
{
  "app": "hirihiri-handicap",
  "version": 1,
  "players": [
    { "id": "p1", "name": "たかし", "baseline": 88, "createdAt": 1760000000000, "archived": false }
  ],
  "rounds": [
    {
      "id": "r1", "date": "2026-10-12", "course": "房総カントリー", "par": 72, "createdAt": 1760000000000,
      "entries": [ { "pid": "p1", "gross": 90, "hcp": 0 } ]
    }
  ],
  "settings": { "decay": 0.9, "clip": 8, "reward": 0, "step": 0.5, "balance": true }
}
```

- `entries[].hcp` は**そのラウンドで実際に使ったハンデ**を保存する(あとで設定を変えても過去の順位が変わらないように)。
- ハンデの計算に使うのは `gross` と `par` だけ。
- ラウンドの並び順は `date` の昇順、同じ日なら `createdAt` の昇順。

## 5. ハンデの計算式

### 5.1 パラメータ

| 記号 | 意味 | 標準値 |
|---|---|---|
| W | 実力推定に使う直近ラウンド数 | 16 |
| r | 1ラウンド古くなるごとの重み(減衰率) | 0.9 |
| P₀ | 申告平均を何ラウンド分として扱うか | 2 |
| C | カット幅(打) | 8 |
| σ₀ | ブレの初期値(打) | 4.5 |
| K | σ₀ を何ラウンド分として扱うか | 1.5 |
| S | シミュレーション回数 | 4000 |
| b | 上手い人ボーナス | 0 |
| step | ハンデの刻み | 0.5 |
| close | 接戦とみなす差(打) | 2 |

### 5.2 ステップ0:パー比に直す

- 各ラウンドの d = グロス − パー
- 初期値 μ₀ = 申告平均 − 72(申告平均が無ければ100とみなす)

### 5.3 ステップ1:実力推定 E

その人が出たラウンドを**古い順に1回ずつ**処理する。

```
E = μ₀
clipped = []
for 各ラウンドの d(古い順):
    x' = clamp(d, E − C, E + C)      # その時点の推定から ±C を超えた分はカット
    clipped に x' を追加
    E = 加重平均(clipped)            # 下の式で毎回計算し直す
```

加重平均(clipped)の式。clipped の**最後のW件**だけを使い、件数を n とする。

```
wᵢ = r^(n − 1 − i)        # i = 0 が一番古い。一番新しいものは r^0 = 1
P  = P₀ × r^n             # 申告平均の重み。ラウンドが増えるほど小さくなる
E  = (Σ wᵢ·x'ᵢ + P·μ₀) ÷ (Σ wᵢ + P)
```

ラウンドが1つもなければ E = μ₀。

### 5.4 ステップ2:ブレ σ

最後に求めた E と、最後のW件の x' を使う。

```
σ² = (K·σ₀² + Σ wᵢ·(x'ᵢ − E)²) ÷ (K + Σ wᵢ)
σ  = clamp(σ, 2.5, 9)
σ' = σ × √(1 + 1 ÷ (Σ wᵢ + P))     # 推定の不確かさを足したブレ。ラウンドが少ない人ほど大きい
```

### 5.5 ステップ3:基本ハンデ

今日の参加者だけで計算する。

```
baseᵢ = Eᵢ − min(E)
hᵢ    = baseᵢ
```

### 5.6 ステップ4:優勝確率の微調整(設定がオンで、参加者が2人以上のとき)

1. 標準正規乱数 Z を S × 人数 個つくる。**シード固定**の乱数を使い、以降の計算ではこの同じ Z を使い回す。
   - シードは「参加者IDの並び + ラウンド数 + 各自のE」から作るハッシュ値。同じ入力なら毎回同じハンデになる。
2. 次を最大40回くり返す。
   - S 回それぞれについて、各自の値 = Eᵢ + σ'ᵢ·Z[s][i] − hᵢ を計算し、一番小さい人を優勝とする(丸めない)。
   - 優勝確率 pᵢ = 優勝回数 ÷ S
   - hᵢ ← clamp(hᵢ − 6 × (pᵢ − 1/人数), baseᵢ − 3, baseᵢ + 3)
   - 全員 |pᵢ − 1/人数| < 0.004 になったら終了。

### 5.7 ステップ5:仕上げ

```
hᵢ   = hᵢ − min(h)
hᵢ   = hᵢ × (1 − b)
hᵢ   = max(0, round(hᵢ ÷ step) × step)
hᵢ   = hᵢ − min(h)                       # 最小を0にそろえ直す
```

これが今日のハンデ。

### 5.8 ステップ6:表示用の数字

決まったハンデで、同じ Z を使ってもう一度 S 回シミュレーションする。今回は実際のスコアに合わせて**整数に丸める**。

```
ネットᵢ = round(Eᵢ + σ'ᵢ·Z[s][i]) − hᵢ
```

- 優勝確率:同点優勝は人数で割って配分(2人同点なら0.5ずつ)。
- 1位と2位の差:同点優勝なら0。
- ヒリヒリ度 = 差が close(2)打以内だった割合。
- 1位と2位の差の予想平均 = 差の平均。

### 5.9 順位

- ネット = グロス − ハンデ の少ない順。
- 同じネットなら同順位(1位が2人なら次は3位)。
- 表示の並びは、同じネットならグロスの少ない人を先にする(順位は同じ)。

### 5.10 乱数の参考実装

どの方式でもよいが、元のアプリは次を使っている。

```js
function mulberry32(seed) {
  let a = seed >>> 0;
  return () => {
    a = (a + 0x6D2B79F5) >>> 0;
    let t = a;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
// 標準正規乱数は Box-Muller:√(−2 ln u)·cos(2πv) と √(−2 ln u)·sin(2πv)
// シード用のハッシュは FNV-1a(32bit)
```

## 7. シミュレーションによる評価

### 7.1 条件

- 4人の真の平均スコア:84 / 90 / 97 / 104(パー比 +12 / +18 / +25 / +32)
- ブレ(標準偏差):3 / 4 / 5 / 6.5打
- 実際のスコア = round(72 + 真の平均差 + ブレ × 標準正規乱数)
- 申告平均 = round(72 + 真の平均差 + 4 × 標準正規乱数)(申告は±4打ほどずれる想定)
- 毎回4人全員が参加し、24ラウンドを1シーズンとする。最初の4ラウンドは集計から除く。
- 200シーズン(シードを変えて)くり返す。

### 7.2 比べる方式

| 方式 | ハンデの決め方 |
|---|---|
| ハンデなし | 全員0 |
| 前回の差を埋める | 前回のグロス − 前回の最少グロス |
| この方式 | 第5章 |

### 7.3 結果(理想はどの列も25%)

| 方式 | 各人の優勝率 | 前回ビリが次に優勝 | 前回優勝が次も優勝 | 2打差以内の決着 | 1打差以内の決着 |
|---|---|---|---|---|---|
| ハンデなし | 87.6 / 11.1 / 1.1 / 0.2% | 0.6% | 78.9% | 21.5% | 13.3% |
| 前回の差を埋める | 19.1 / 22.5 / 27.1 / 31.3% | 48.7% | 11.5% | 34.2% | 21.5% |
| **この方式** | **22.2 / 23.8 / 26.3 / 27.7%** | **28.2%** | **25.5%** | **41.4%** | **24.8%** |

「前回の差を埋める」方式では、前回ビリの人が約半分の確率で次に勝ち、勝ち負けが交代制になる。この方式では誰が勝つか読めないまま、4割の決着が2打差以内になる。

### 7.4 合格ライン(作り直したときのチェック)

- 各人の優勝率がすべて17%〜33%に入る。
- 前回ビリが次に優勝する率が36%未満。
- 2打差以内の決着が35%以上。

## 8. テスト項目

1. ラウンドが無く微調整オフなら、ハンデ = 申告平均の差(85 / 92 / 100 の3人 → 0 / 7 / 15。申告 84 / 92 / 100 なら 0 / 8 / 16)。
2. 一番上手い人のハンデは必ず0、ハンデは刻み(0.5)の倍数。
3. 微調整オンなら、各自の優勝確率は 1/人数 ±5% 以内。
4. 同じ入力なら同じハンデ(再現性)。
5. 2人が5ラウンドずつ同じスコア(84と92)を出したあと、2人目が1回だけ115を叩いても、ハンデの増加は0より大きく1.5打以下。
6. パー70で82とパー72で84は同じ実力推定になる。
7. 順位:A 85(ハンデ0)、B 93(ハンデ8)、C 99(ハンデ16) → C 1位、AとB 2位タイ。
8. 第7章の合格ラインを満たす(30シーズン × 20ラウンドでも可)。
